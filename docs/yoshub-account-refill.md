# 账号补号与快乐首字分组设置

本版本通过号商公开 API 实现截图可确认的规则和设置。服务商内部未公开的算法不作为实现依据。

## 分组规则与套餐轮转

补号面板顶部选择当前分组。各组分别保存开关、补号方式、监测阈值、时间窗口、预算、冷却、在途上限、推送设置、通知和订单记录。切换分组前须保存修改。原规则和在途订单保留；新规则默认关闭自动购买，只继承原规则的连接信息，保存后可独立更换 Key。跨组投递的在途订单会抵扣目标分组缺口；同一号商钱包的本地待提交预占也会合并核对。

在“补号规则”开启套餐轮转，添加 1–20 个有序步骤，每步可连续下单 1–100 个。例如 `Pro20x × 1 → Pro5x × 2` 会持续按 `20x、5x、5x、20x……` 自动下单。轮转与容量、固定储备、定时模式组合使用，每笔仍遵守触发条件、冷却、单价上限和本组预算。套餐不可用或预算不足时等待，不跳过当前轮次。

轮转位置与订单、预算预占在同一次持久化中保存；重启接续，网络失败重试仍用原幂等键和套餐，不重复占轮次。手动补号不推进轮转。调整顺序、数量或开关后从第一步开始，调整其他设置保留位置。轮转按自动下单计数，号商确认失败的订单也计入该次下单。

分组接口在既有 `/admin/accounts/refill` 及其动作接口添加 `group_id` 查询参数；省略时兼容原规则。新规则存储在独立 settings 键，所有规则与旧版共用同一个 PostgreSQL advisory lock，无数据库结构迁移。回滚前应先停用新增分组的自动规则并处理其在途订单；旧程序只处理原规则。

## 未分配账号刷新

未分配到任何分组、状态正常、具有 refresh token 的 OpenAI OAuth 账号，默认每 15 秒扫描一次；启动时立即扫描。刷新成功后查询并保存额度，不自动分配分组或改变账号预设。已分组、影子、PAT、Agent Identity、已到期自动暂停或处于临时冷却的账号跳过。沿用共享的令牌锁、限流、并发限制和失败退避；大号池或慢请求时实际完成时间可能超过一个扫描周期。`TOKEN_REFRESH_UNGROUPED_CHECK_INTERVAL_SECONDS=0` 可关闭。

## 使用入口

- 账号管理 → 补号规则：连接与分组、补号规则、推送设置、手动补号、企业微信通知、消费与进度。账号列表也提供独立“手动补号”入口。
- 快乐首字 → 按分组单独设置：勾选 OpenAI 分组，独立设置开关和等待区间，取消勾选恢复全局默认。

补号默认只监测，不自动购买。接管补号时先停用号商原有自动补号，再开启本功能。配置中的 API Key 留空表示保留；替换时校验号商账户身份。有在途订单时只能更换同一号商账户的 Key，避免幂等键换账户后失去去重作用。

## 第一版规则

| 设置 | 默认值 |
| --- | --- |
| 模式 | 并发与额度 |
| 最低未来健康储备 | 1 |
| 未来健康储备上限 | 20 |
| 提前补号 | 原始租期结束前 30 分钟 |
| 5h / 7d 剩余额度下限 | 15% / 15% |
| 目标并发利用率 | 85% |
| 并发持续观察 | 30 秒，可设置 1–3600 秒 |
| 检查间隔 / 下单冷却 | 60 秒 / 300 秒 |
| 在途任务上限 | 1 |
| 默认套餐 / 单价上限 | Pro5x / 60 积分 |
| 每日预算 / 提交次数上限 | 3000 积分 / 50 次 |
| 定时模式 | 每 60 分钟补 1 个 |
| 导入并发 / WS / 指纹 | 60 / HTTP bridge / full |

“并发与额度”根据健康储备、账号真实租期、5h/7d 剩余额度和当前并发计算缺口。每秒独立采样，利用率连续达到目标并满观察时长才允许按并发扩容；低于目标、采样失败、间隔超过 2 秒、配置变更或进程重启均重新计时。下单前再次读取负载，防止突发已结束后购买。检查间隔、冷却、在途上限和预算仍生效；临期或储备缺口不受并发观察窗口限制。“固定健康保有量”检查健康储备、临期和额度，不按并发扩容。“定时补号”按周期分批补入配置数量。

临期号可以继续调度，但不计入未来储备。在途任务抵扣缺口；即使保有量及上限均为 1，也允许临期号与替补号短暂共存。禁用、暂不可调度和低额度账号不算健康储备；影子账号不纳入计数。额度来自现有有效账号快照，未知或已重置/过时的额度不冒充准确数据，面板显示空值。

北京时间运行窗口支持跨午夜。暂停监测或关闭自动购买不会丢弃已受理订单；暂停推送会同时停止新下单，已完成的交付等待恢复推送。正在执行的订单使用下单时的投递配置快照。

## 导入过期时间

推送设置的随机代理只从未绑定账号的有效代理中分配，每个代理最多由二开自动分配给一个未删除账号。选择和创建账号在同一个事务内，与受限管理 Key 的随机/最空闲分配互斥。没有空闲代理时，原订单保留为导入失败，可在添加代理或释放绑定后重试，不自动改为直连，也不重新购买。原生账号推送及显式指定代理保持兼容，已有绑定不自动重排。

从 `0.2.19-yoshub.native-expiry.1` 起，账号编辑中的原生 `expires_at` 保存实际暂停时间。OpenAI OAuth 账号导入时独立记录号商租期，再将导入截止（或更早的号商租期）加保留分钟数写入原生过期字段。调度、SQL 过滤、容量统计和自动暂停直接使用该值，不再重复加宽限；OAuth token 的有效期不变。

账号编辑 → 过期时间 → 设置到期后保留时间：保存 0–1440 分钟会从原始截止重新计算一次，并更新编辑框。直接修改过期时间按填写值生效，后续租期同步或网站原样回写不覆盖人工设置；再次保存保留分钟数则重新计算。已暂停账号不会自动恢复。提前补号仍依据号商回收时间，不包含保留时长。

网站推号兼容绑定导入 Key 与其导入账号：旧版 Key 使用逻辑标识 `legacy`，受限 Key 使用稳定 Key ID（轮换不改变身份），不保存密钥明文。该 Key 在详情、完整/精简列表、更新响应及导出中读到原交付时间；JWT 后台和其他 Key 读到实际原生过期时间。原样回传交付时间不会累加保留时长或覆盖人工截止，修改交付时间时只计算一次。兼容视图不用于网关调度及内置补号；权限、分组、调度开关和优先级使用原流程。

租期、保留时长、Key 绑定及截止模式不进入原生 `extra` 响应和导出。到期策略和原生时间在同一行锁事务内保存并写入调度 outbox；普通编辑、批量 extra 更新和旧快照上的令牌刷新不清除或覆盖受管元数据。JWT 备份还原保持导出的实际原生到期时间。

旧版账号转换前继续支持内部宽限，精简调度快照保留所需字段。数据转换将此前有效截止写入原生字段，不重复延长，保留租期与调度状态；外置旧账号仅在审计能确认导入 Key 时建立绑定，未知来源留待核对。

## 按套餐设置额度下限

补号规则保留通用 5h / 7d 下限，并可分别为 Pro5x 和 Pro20x 启用独立百分比（0–100，支持小数）。关闭某套餐覆盖或无法识别套餐时使用通用值；旧配置不启用覆盖，行为不变。设置随各分组规则独立保存。

每个被检测账号按自己的套餐匹配，优先使用购买套餐记录或关联订单，再识别账号 `plan_type`（pro5/pro5x/prolite 对应 Pro5x，pro20/pro20x/pro/chatgptpro 对应 Pro20x）。不会用下一次购买的套餐套用整个池。任一有效额度窗口的剩余百分比低于该账号下限时不计入健康储备；零下限关闭该窗口的低额度触发，未知/过时额度不伪装成低余额。套餐轮转顺序保持原设置。

新订单的补号备注记录实际采用的套餐阈值，评估列表显示匹配套餐和下限。新导入 API 账号保存购买套餐，已有订单也可识别。

## 真实租期同步

公开 Key API 的 `GET /api/customer/developer/v1/refills/{id}` 返回 API 订单的 `expires_at`，不能读取网站创建的订单。网站订单在该接口实测返回 `404 API order not found`；网站的客户状态接口要求登录会话，Bearer Key 不能替代会话。

本功能每 5 分钟轮询最多 5 个已导入 API 订单，轮转检查，手动“同步余额、租期与规则”也会检查；自动监测关闭时只由手动检查触发。先验证本地订单与账号关联，再原子更新私有租期元数据。失败、404、无效响应保留旧租期；429 遵守退避。网站推送账号使用导入时记录的租期，仍保留的旧版原始租期标记也可识别。面板明确区分“号商 API”“导入租期记录”“本地设置 · 未识别号商租期”，不把手动到期日期冒充号商数据。

## 钱包、密钥和任务

顶部展示总余额、冻结积分、可用积分及更新时间。旧钱包 API 的金额除以 100 换算积分；补号报价直接使用积分，保留小数。API Key 只保存加密值，响应不返回明文；从号商 Key 列表匹配有效期，面板显示北京时间到期时间和剩余天数。接口无法返回时显示未知。

任务展示提交、排队、处理、人工核对、等待交付、推送暂停、导入、成功及失败等真实状态和耗时，不推测百分比或预计完成时间。每日预算按北京时间归属到提交日，仅统计本功能的订单；钱包余额包含其他消费。在途预占属于提交当日，不跨天重复计费。

“消费与进度”按每页 10 条展示当前分组任务，支持页码和前后翻页；15 秒自动刷新保留当前页，切换分组或重新打开回到第一页。每条任务显示下单原因，新订单另保存下单前最终评估的备注：定时周期、并发数/利用率/阈值/观察时长，或最低储备缺口及临期、已到期、低额度、不可调度数量。原因和备注随订单持久化，重试或修改规则不改写历史；旧订单显示已保存原因，缺失时明确提示，不用当前状态反推。现有历史保留上限不变。

## 重试和一致性

1. PostgreSQL session advisory lock 串行化所有实例的配置及调度。
2. 先持久化订单 UUID、固定报价版本、配置快照和预算预占，再调用付费接口。
3. 网络超时/5xx 沿用原幂等键和请求体。重启从持久化任务继续；429 遵守 Retry-After。
4. 号商 `review`、拒绝待核对和导入失败阻止新增订单。确认失败后释放本地积分预占，提交次数保留。
5. 新账号先停用并禁止调度，写入恢复标记，完成分组和推送设置后才启用。创建后中断通过标记找到原账号，避免重复导入。
6. “重试原任务”沿用原订单；收到报价冲突等拒绝且没有号商任务 ID 时，须先向号商核对没有订单/扣款，勾选确认后可释放本地预占，再按新报价重新评估。已受理和状态不确定的网络请求不能用该操作放弃。
7. 配置写入使用 revision 防止多页面覆盖。刷新进度不覆盖未保存的编辑。

本地测试使用替身 API 验证购买与交付流程。生产验收只读余额、报价、有效期及规则预览，不为测试购买账号。

## 管理 API

仅完整管理员可访问；受限管理 Key 不自动继承此能力。修改配置的请求体不进入审计日志。

| 方法与路径（均位于 `/api/v1/admin/accounts`） | 行为 |
| --- | --- |
| `GET /refill` | 读取脱敏配置、钱包、报价、评估、任务 |
| `PUT /refill` | 保存 `{config, api_token, revision, wecom_webhook}`；Key 和 Webhook 留空保留 |
| `POST /refill/check` | 检查已保存规则和号商元数据，不下单 |
| `POST /refill/manual` | `{request_id, plan, revision}`；按保存的设置预留 1 个手动订单，由现有任务流程购买及导入 |
| `POST /refill/jobs/:job_id/retry` | 重新处理原任务 |
| `POST /refill/jobs/:job_id/dismiss` | 仅未返回供应商任务 ID 的拒绝请求；必须 `confirm_not_accepted: true` |
| `GET /:id/expiry-grace` | 读取账号保留分钟及有效调度截止 |
| `PUT /:id/expiry-grace` | 保存 `{minutes: 0..1440}` 并原子更新实际原生过期时间 |

快乐首字设置在原接口中增加 `group_overrides` 数组，各项包含 `group_id`、`enabled`、`min_delay_ms`、`max_delay_ms`。省略该字段的旧客户端保留已有覆盖；显式空数组清除覆盖。请求按 API Key 所属分组匹配，不能用共享账号的全部分组推断。原有 SSE 协议范围、真实输出计时和错误处理保持一致。

## 手动补号、排序和套餐标识

手动补号每次选 Pro5x 或 Pro20x 购买 1 个，完整继承保存的并发、分组、代理、优先级、倍率、WS、指纹、保留时间、状态、模板和模型映射。不会更改自动规则的套餐或开关；自动补号或监测关闭时仍可使用，绕过自动需求、时段和冷却，保留推送开关、配置版本、预算、单价、在途数量和代理容量检查。页面有未保存规则时先保存。

请求标识由毫秒时间戳和 UUID v4 组成，以冒号分隔，24 小时内可重试。浏览器会话保存未确认的请求，超时或重新打开弹窗仍复用它。后端在跨实例锁内持久化预算和任务配置快照，并为请求派生固定订单 UUID；24 小时内的手动回执不受 200 条普通历史限制，过期标识拒绝新下单。重试不会因为配置已修改而重复购买。

“查看 / 调整内部排序”中的“一键恢复全部自动排序”跨全部分组、状态和分页清除手动排序覆盖；原生 priority 字段保留。账号标识将号商 pro5/pro5x 映射到紫色 Pro 100，pro20/pro20x 映射到 Pro 200，仅调整 OpenAI 显示，不改凭据或供应商套餐参数。

## 企业微信通知

配置指定群机器人的官方 Webhook，地址加密保存、响应不回显且配置请求体不进入审计日志。“开始补号”和“积分不足 / 低余额”分别有开关，默认关闭；默认预警阈值 100 积分，可设置 0–10000000。

开始处理自动或手动订单时发送套餐、积分、并发、分组 ID、任务号和时间。余额通知每分钟读取号商钱包，不依赖自动购买或监测开关；达到阈值或下单前积分不足时通知，持续不足不重复提醒，恢复后重新触发。页面读取评估不会触发钱包查询。

消息采用与 NewAPI 相同的企业微信 text 格式，校验 HTTP 和 errcode。发送限时 5 秒，失败不取消订单，面板展示通知状态。企业微信无幂等键，因此持久化发送标记后只尝试一次，避免重试或蓝绿重叠导致刷屏；发送超时可能无法确认送达。关闭通知不会取消在途补号。

## 本地账号评估与额度一致性

“消费与进度”每 15 秒 GET 本地状态，即使号商检查或手动补号请求仍在等待也继续刷新。GET 不获取任务锁，不调用号商、额度探针或上游；直接从 Sub2 数据库的账号及 codex 5h/7d 快照、Redis 并发重算评估。局部读取最长 3 秒，失败明确显示错误，不把旧表冒充实时数据。缺失、无效或已重置窗口的额度显示未知。订单处理、独立的后台钱包通知检查及号商租期同步按各自周期访问外部接口，不与页面评估刷新绑定。

自动下单在号商报价 / 身份请求完成后再次读取本地需求，避免慢请求期间额度或账号状态已改变仍按旧缺口购买。主动额度探针的结果先完成本地持久化再返回页面，修复先显示新值、随即读回旧值的窗口；补号 GET 也不再复用 settings 中落后的评估结果。并未强行把额度设为单调下降，真实重置或新的上游有效观测仍正常显示。
