# Yoshub 0.2.20-yoshub.25：King SmartWS 合并

本次从桌面 King 源码移植独立 SmartWS 池及相关传输优化，保留 Yoshub 的账号选择、IPv6/代理出口、补号、分组、自定义重试入口、客户端断开取消上游和现有计费。不是 King 整仓替换。

## SmartWS 独立池

HTTP 请求尝试 WS 的物理连接池与原生 WS 入站连接池分开。外层账号/用户/分组的并发准入继续生效，独立池的连接预算不会把账号配置并发改成 2000。

- 全局连接容量按近期活跃上游身份自适应：`min(4096, max(128, activeAccounts * 256))`。
- 同一上游账号最多 256 条连接，同一完整复用身份最多 64 条。稳定账号预算按目标主机与 ChatGPT Account ID；无该 ID 时按凭据摘要。代理、会话、认证头、分组和 API Key 等仍参与连接隔离。
- 排队最多 256 个请求、每账号 32 个、排队消息字节合计 64 MiB、最长 2.5 秒。64 MiB 是纳入排队的消息字节预算，不是进程总内存承诺。
- 无匹配连接且不能立即握手时，完整请求快速退回 HTTP。复用按相同身份公平等待，新建连接按账号 FIFO 准入。
- 每个稳定上游账号最多 2 个并行握手，0.9 次/秒、突发 2；失败退避 5–60 秒，恢复时单探针。
- 空闲连接 5 分钟过期，生命周期 20 分钟；容量紧张时跨身份回收闲置连接，不中断正在生成的请求。
- 未发送生成请求时才可退回 HTTP；发送后断连不自动重放，避免重复执行/计费。断开取消会关闭实际 socket。
- 监控新增独立池容量、活跃、排队数量/字节、复用、回收、快速 HTTP 回退和握手退避。握手诊断只记录脱敏摘要。

上述预算是单进程本地资源限制。多个进程/副本各有自己的池，不能据此声称单号具备 2000 个真实上游并发额度。

## 续聊边界

按用户补充要求，删除 Yoshub 的 HTTP 转 WS `previous_response_id` 续聊增强。SmartWS 不维持响应 ID 到 socket 的历史。

- 完整历史请求可以复用空闲 WS，普通多轮聊天正常。
- HTTP 的 `previous_response_id`/`conversation` 不进入 SmartWS；API Key 的原有 HTTP 历史能力保留，OAuth HTTP 的原有校验生效。
- 原版和 King 已有的原生 WS 续聊保留。

## 429 与错误处理

首次 OpenAI OAuth 429 后，同一请求最多再恢复 3 次、恢复窗口 30 秒，同账号重试与换账号共享预算；成功的 WS 回合后重新开始下一回合预算。已正常生成的响应不因恢复预算到期被掐断。

自定义重试入口保留。它控制同账号尝试上限；设置 0 禁止同账号重试，不等于禁止换账号。请求级 429 总预算是额外上限，配置 10 次也不能突破 3 次恢复预算。其他错误继续使用各自原有规则。

完整保留 `Retry-After` 秒数和 HTTP 日期，不再截为 8 秒。所需等待超过剩余预算时结束恢复，不提前重打上游。Cyber 特定模型权限 403 与凭据失效、内容拒绝分类分开，不惩罚其他正常流量。加密历史错误支持消息/嵌套协议加密片段，保留普通正文与工具数据；已发送的 SmartWS 失败不靠重发掩盖。

## 分组首字延迟优化

分组管理 → 首字优化，包含“启用智能 WS 优先”和新增“提前透传真实限额事件”。新增开关默认关闭，按分组持久化，不需要数据库结构迁移。

启用后仅立即转发上游真实、完整、前置的 `codex.rate_limits` SSE 帧；不伪造限额，不调整用量。可与快乐首字同时启用，写入共用锁。语义事件口径可以计入真实限额事件到达时间；真实可见输出口径仍等待模型可见内容。网关自己的快乐首字不计入本站 TTFT。先发限额事件后发生错误，使用流内失败事件结束，不拼接 JSON 错误；后续尝试若返回成功的 JSON Responses 对象，会转换成 SSE 输出完成事件并保留上游用量。

## 连接清理与启动保护

- 共享 HTTP 客户端按闲置 10 分钟、目标上限 4096 清理，关闭空闲连接，保留活动请求。
- WS 代理客户端缓存可用 `OPENAI_WS_PROXY_CLIENT_CACHE_MAX_ENTRIES` 配置，默认 256，有效范围 1–16384，闲置 TTL 15 分钟。
- `GATEWAY_SCHEDULING_PRESERVE_PROCESS_SLOTS=true` 默认开启。启动不会删除其他实例的并发槽位；已有过期清理与租约回收继续工作。
- 异常退出后普通槽位按既有 TTL 回收；等待计数在停止刷新后按 TTL 过期。这不是立即识别所有进程崩溃的分布式存活协议。
- 单独构建 `0.2.20-yoshub.24`（原 .23 + 启动槽位保护）作为回滚镜像，避免重新启动旧的不安全版本。
