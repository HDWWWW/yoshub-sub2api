# IP 容量、内部排序与租期显示

IP 管理页在绑定账号数下面显示上限，点击可单独设置；勾选多条后使用“批量设置绑定上限”。每条代理默认 1，允许 1–100000，每批最多 1000 条。设置保存在扩展表 `yoshub_proxy_binding_limits`。随机、最空闲和自动补号共用数据库事务锁，只分配启用、未过期且绑定数小于上限的代理。停用但未删除的账号仍占名额，软删除或解绑释放；调低容量不解除已有绑定。原生显式 `proxy_id`、导入导出和账号推送保持兼容，限制按代理记录计算，不探测号商背后重复的出口 IP。

账号页“查看 / 调整内部排序”按分组预览当前候选池的自动优先级与生效优先级。自动规则按实际到期从早到晚，其次无到期、最后已到期。账号行快捷修改、编辑窗口改变优先级、批量修改优先级和排序窗口保存均开启手动覆盖；数值越小越优先，0 可优先于自动序号。恢复自动清除覆盖，保留原生字段。会话绑定、模型能力、额度、并发及同级负载仍影响实际请求选择；预览不是固定全局请求队列。

手动值保存在私有 `yoshub_manual_scheduling_priority` 元数据，原生 DTO / 导出不暴露该键。原生推送的 `priority` 仍正常保存，不会自动开启或清除手动覆盖；持久化在行锁内保留最新覆盖，防止并发旧表单或号商同步冲掉手动设置。只有完整管理员显式提交 `yoshub_priority_mode=manual|auto` 才能变更覆盖，manual 必须同时提交 0–9999 的整数 priority。

实际选号读取的精简候选缓存与完整账号缓存都保留手动覆盖，包括 0。保存或恢复自动会更新账号缓存及平台修订号，已加载候选的工作进程在下次读取时刷新排序，无需重建分组成员；避免页面预览正确、实际调度仍沿用自动顺序。

账号列表和保留时间设置分别显示“号商回收时间”与“实际到期时间”。实际到期复用网关和自动暂停使用的 `SchedulingExpiresAt`：取已识别租期和本地截止中更早者，再加该账号保留分钟。没有来源记录的本地时间不标为号商回收时间；未启用自动暂停时明确提示。原生 `expires_at` 不改写，避免重复加保留时间。列表通过批量接口加载扩展数据，不逐行请求。

完整管理员扩展接口：

- `POST /admin/proxies/binding-limits/query`：`{proxy_ids:[...]}`。
- `PUT /admin/proxies/binding-limits`：`{proxy_ids:[...],max_accounts:3}`，整批事务保存。
- `POST /admin/accounts/scheduling-metadata`：`{account_ids:[...]}`，返回来源、保留时间、实际截止、手动覆盖。
- `GET /admin/accounts/scheduling-preview?group_id=...&platform=openai`：返回基础排序，复用实际排序函数。

发布沿用 [蓝绿脚本](../deploy/bluegreen/README.md)：新槽位健康后切流，旧槽位自然排空再停机。新增表与旧应用兼容；账号和代理不批量迁移。
