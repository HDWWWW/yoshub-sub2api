# 账号风控检测

账号管理顶部的“风控检测”按 OpenAI 分组保存独立规则。新规则默认关闭，管理员选择分组、调整参数并保存启用。关闭弹窗不停止服务器检测；关闭规则不会重新开启已停用账号。

## 两个及以上可调度账号

按调度器有效优先级取前两个账号，包括到期优先级、手动优先级、分组反转。每秒读取最新 Redis 并发槽位，使用率为当前并发 / 账号并发上限。默认首位低于 60%、次位达到 90%，连续 10 秒后，立即按下方配置的模型、思考强度、测试消息和期望内容复测首位账号；只有完整成功回复不含期望内容才处理。复测通过、网络错误或回复不完整均不会据此停调度。

容量异常的首次复测无需再等待测试间隔，持续异常的后续复测按配置间隔执行，短暂恢复不会绕过该间隔。启用“容量异常复测不达标时，仅提醒，不停止调度”（`capacity_notify_only`）后，复测不达标只通知企业微信并记录事件；默认关闭，关闭时沿用停调度行为。

阈值可设为 1–100%，持续时间可设为 1–3600 秒。条件中断、读失败、超过 3 秒未采样、账号/身份/容量/顺序或检测实例变化均重置计时。同优先级或无限容量不会判定异常。已停调度、过期、冷却、达到调度阈值的账号不属于候选。

这是一条管理员选择启用的容量启发式规则。会话绑定、模型兼容性和流量分布同样可能导致使用率不均，触发本规则不能证明上游已对账号实施风控。

## 仅一个可调度账号

默认每 300 秒发送“请只回复数字 21，不要输出其他内容。”，检查完整可见回复是否包含 `21`，区分大小写。消息、期望内容、模型、思考强度和间隔都可修改。首次启用或单号身份改变后等待完整间隔；间隔范围为 10–86400 秒。

测试参数同时供容量异常复测使用。启用“单账号定时测试不达标时，仅提醒，不停止调度”（`probe_notify_only`）后，完整成功回复不达标仅通知并保留调度。两个“仅提醒”开关互相独立，默认关闭；开启后均主动发送企业微信通知，不受“异常停调度时通知”开关影响。

测试复用现有 OpenAI 账号连接测试的认证、URL、代理、TLS、账号请求头覆盖和模型映射。支持 OpenAI OAuth 与普通 API Key 的 Responses/Chat Completions 文本路径；Excel/BPS 和图片模型不支持，记录为检测未完成。测试占用正常账号并发槽，90 秒超时；全站跨实例同时最多一条风控测试，不自动重试或跟随重定向。测试消耗上游账号额度，与既有管理员连接测试一致，不记入下游用户账单。

只有收到完整成功终态且可见文本不匹配，才按对应开关执行停调度或仅提醒。401、429、其他上游错误、断流、取消、容量繁忙、过大响应均记为检测未完成，不冒充文本不匹配。不会匹配 reasoning、usage 或错误中的期望文字，不保存完整回复或凭据。测试期间关闭或修改规则、账号/身份/成员发生变化，旧结果作废；容量复测还核对触发时的前两个账号及顺序。短暂锁冲突仅重试保存结果，绝不重新发送生成。

## 上游响应模型不一致

分组风控启用后，可单独选择“关闭此项检测”“立即停止账号调度并通知”或“立即通知，继续调度”。新增选项默认关闭，已有配置缺少 `model_mismatch_action` 时也按关闭处理。该选项独立于容量和定时测试通知开关：`stop` 和 `notify_only` 均创建企业微信通知，机器人仍复用对应分组的自动补号规则。

比较实际发送到上游的模型（经过渠道、账号和协议映射后的名称）与上游原始响应的模型声明，沿用使用日志的模型比较规则。流式请求在收到模型声明时处理，无需等待生成完成、账单入队或定时探针；覆盖 Responses、Chat Completions、Messages 转换、SmartWS/原生 WebSocket 及其 HTTP 回退。未声明模型、模型名大小写差异及既有比较规则认可的别名不触发；这不是比较回答正文，也不判断回答质量。

停调度模式只在当前账号身份、分组成员关系仍有效时操作，事务内同时保存停调度、处理记录与 scheduler outbox；更新调度快照后阻止后续调度，已接入的请求继续完成。通知失败不会恢复调度。仅通知模式不更改账号调度字段，其他容量和定时测试规则仍独立生效。

首次发现即生成待发送通知并唤醒通知工作器，不另等定时采样。发送仍遵守现有全站串行、至少间隔 3 秒的机器人限速；拥塞时可能排队。仅通知模式将同一账号一分钟内的重复异常合并并累计次数，第一条立即入队，持续异常在下一分钟可再次通知。关闭规则或本项检测会取消尚未开始发送的通知；已认领的消息可能完成。重启不重复发送结果不确定的消息。通知和最近处理记录明确区分“已停止调度”与“仅通知”。

## 停调度、状态与恢复

仅将异常账号的 `schedulable` 设为 false，现有请求继续完成，不自动恢复。这个开关是账号级的，账号的其他关联组也受影响。需要恢复时在账号列表手动开启调度。

面板展示实际启用状态、容量、连续异常起点、下次测试、上次结果和最近 50 条风控处理记录。配置编辑不被后台刷新覆盖，保存使用 revision 防止覆盖其他管理员的修改。

状态与配置保存在现有 settings 的 `account_risk_detection_v1`，无新表/迁移。独立 PostgreSQL advisory transaction lock 协调实例；停号、事件、scheduler outbox 同事务提交并更新调度缓存。上游请求不持数据库锁。最多 32 个规则，异常数据库状态不执行停号。

管理接口：完整管理员访问 `GET /api/v1/admin/accounts/risk-detection?group_id=ID`；`PUT` 同地址，body 为 `{ "revision": 0, "config": { ... } }`。受限管理员密钥不允许访问。

该功能独立于 SmartWS、补号、吸能、旧探针和恢复逻辑，不修改它们的开关。发布使用本机受限构建的固定镜像，服务器只拉取和运行；回退旧应用不删除配置和已停调度状态。
