# 账号风控检测

账号管理顶部的“风控检测”按 OpenAI 分组保存独立规则。新规则默认关闭，管理员选择分组、调整参数并保存启用。关闭弹窗不停止服务器检测；关闭规则不会重新开启已停用账号。

## 401 独立提醒

打开分组的「401 独立提醒」后，账号业务请求、获取模型列表、手动测试、自动风控探测、用量查询和凭据刷新实际收到上游 401 时，只为当时仍启用调度的活跃账号排队发送企业微信提醒。触发停调的那次 401 仍提醒，之后的 401 静默，恢复调度后再次收到 401 会重新提醒。业务请求使用请求分组，后台操作使用账号已开启提醒的关联组。风控面板手动测试使用该组已经保存的提醒开关。

全局队列每 3 秒发送一条。账号后来停调不会撤回已入队的提醒。号商回收时间仍限制自动探测，在途响应和手动操作按收到 401 时的调度状态判断。

## 两个及以上可调度账号

按调度器有效优先级检查所有账号，包括到期优先级、手动优先级、分组反转。每秒读取最新 Redis 并发槽位，使用率为当前并发 / 账号并发上限。默认前位低于 60%、任意后位达到 90%，持续 10 秒后，立即暂停所有满足条件的前位账号，再按下方配置的模型、思考强度、测试消息和期望内容依次复测。完整回复包含期望内容才恢复调度；答错、网络错误、限流、繁忙或回复不完整均保持暂停，按配置间隔继续复测。

暂停队列跨实例持久化，服务重启或测试中断不会自动放行。恢复使用暂停所有权标记和账号版本校验，不能覆盖管理员手动调整、账号身份变更或其他风控停调；关闭或修改规则不会自动恢复已暂停账号。已运行请求继续完成。容量恢复后的再次检测仍保留独立冷却间隔。

启用“容量异常仅提醒”（`capacity_notify_only`）后跳过预先暂停，复测不达标只通知并记录事件，仍独立于单账号测试的处理选项。

阈值可设为 1–100%，持续时间可设为 1–3600 秒。条件中断、读失败、超过 3 秒未采样、账号/身份/容量/顺序或检测实例变化均重置计时。同优先级或无限容量不会判定异常。已停调度、过期、冷却、达到调度阈值的账号不属于候选。

这是一条管理员选择启用的容量启发式规则。会话绑定、模型兼容性和流量分布同样可能导致使用率不均，触发本规则不能证明上游已对账号实施风控。

## 单个或全部账号定时检测

“启用账号定时检测”（`probe_enabled`）可单独开关；仍需分组风控总开关开启。检测范围 `probe_scope` 可选 `single`（原模式，仅在分组剩一个可调度账号时检测）或 `all`（并发检测此分组全部可调度账号）。旧配置缺少这两个字段时按开启、`single` 处理，保留原行为。关闭定时检测不影响容量异常复测、业务 429 或模型响应检测，不恢复已停调账号；关闭或切换范围使正在执行的旧配置结果失效。

默认每 300 秒发送“请只回复数字 21，不要输出其他内容。”，检查完整可见回复是否包含 `21`，区分大小写。消息、期望内容、模型、思考强度和间隔都可修改，间隔范围为 10–86400 秒。全部模式为每个账号持久化独立的到期时间和上次结果，首次启用、新增账号或该账号身份变化后等待完整间隔；其他账号变化不重置它的计时。已停调、过期、冷却或达到调度阈值的账号不参与定时检测。每秒扫描到期账号，同一轮到期的不同账号并发执行；每个账号本次完成后再加设置的间隔安排下次，慢账号或连续重试不阻塞其他账号及它们的后续轮次。同一账号跨分组、实例及手动/容量测试最多一个在途检测；重复分组按最早到期规则处理。容量异常仍优先暂停，容量复测和原单账号/手动测试保留一个串行任务，可与其他账号的全部模式检测同时运行。

测试参数同时供容量异常复测使用。启用“定时测试回复不达标时，仅提醒，不停止调度”（`probe_notify_only`）后，完整成功回复为空或不含期望内容时仅通知并保留调度；关闭时只停止本次被测账号的调度。其他账号的检测与调度继续，不因一个账号失败而停止整组。两个“仅提醒”开关互相独立，默认关闭；开启后均主动发送企业微信通知，不受“异常停调度时通知”开关影响。

“回复不匹配后立即重试次数”（`probe_mismatch_max_retries`）可设为 0–20，默认 0，旧配置缺少字段时也为 0，适用于两种定时检测范围。次数指首次完整回复不匹配后的额外检测次数；设为 2 时最多检测 3 次，任一次匹配立即通过，全部不匹配才按 `probe_notify_only` 停调或仅提醒。复测过程中收到真实上游 HTTP 429，立即停止该账号调度，不再进入连续 429 重试，且独立于 `probe_notify_only` 与 `probe_429_stop_enabled`；通知沿用 `notify_enabled`。网络错误、其他上游错误、超时、断流和并发位繁忙结束本轮，记为检测未完成，不据此停调。每次复测前重新检查规则版本、检测开关、账号身份与分组关系；过期结果不能停调。复测不额外等待，每次有独立 90 秒超时并重新获取正常账号并发槽；整个检测的账号互斥期限覆盖所有复测，下一轮间隔从本轮结束起计算。手动测试与容量复测不启用此重试选项。

“定时测试消息连续 429 时停止对应账号调度”（`probe_429_stop_enabled`）默认关闭，最大重试次数 `probe_429_max_retries` 可设为 1–20，默认 3，适用于两种定时检测范围。同一账号同一次定时检测首次明确收到上游 HTTP 429 后立即重试，不增加等待或退避。设为 5 时，首次请求加最多 5 次重试全部返回 429 才关闭该账号调度，无需并发满载。停调原因记录在历史中，通知沿用 `notify_enabled`。本项独立于回复不达标“仅提醒”和业务请求的滚动 429 计数。收到完整回复后转入内容匹配及上述不匹配复测规则；其他错误结束本轮，不跨账号或定时周期累计；本地并发位繁忙、网络错误、取消、超时和未用尽次数的 429 不触发此项停调。每次重试前及停调前重新校验配置、账号身份和成员关系，首次请求及其连续 429 重试共用一个并发位和 90 秒超时；后续不匹配复测单独计时。手动测试与容量复测保持原有行为。旧配置缺少字段时按关闭、3 次处理。

测试复用现有 OpenAI 账号连接测试的认证、URL、代理、TLS、账号请求头覆盖和模型映射。支持 OpenAI OAuth 与普通 API Key 的 Responses/Chat Completions 文本路径；Excel/BPS 和图片模型不支持，记录为检测未完成。测试占用正常账号并发槽，单次检测最多 90 秒；全部模式可同时检测不同账号，每个账号跨实例最多一条风控测试。按上述配置立即重试定时测试的完整不匹配回复或初始连续 429，不重试其他失败或跟随重定向。测试消耗上游账号额度，与既有管理员连接测试一致，不记入下游用户账单。

定时测试和容量仅提醒模式在收到完整成功终态且可见文本不匹配时处理，定时测试另支持上述连续 429 停调规则。容量暂停模式则只有完整回复匹配才恢复。401、未触发停调规则的 429、其他上游错误、断流、取消、容量繁忙、过大响应均记为检测未完成，不冒充文本不匹配。不会匹配 reasoning、usage 或错误中的期望文字，不保存完整回复或凭据。测试期间关闭或修改规则、被测账号/身份/成员关系发生变化，旧结果作废；容量仅提醒模式还核对触发时的比较账号及顺序；已经暂停的账号独立复测，不再依赖后位账号。短暂锁冲突仅重试保存结果，绝不重新发送生成。全部模式下检测中断仅推迟该账号下一次检测，其他到期账号继续执行。并发返回结果在原事务锁内逐一保存，短暂写锁竞争只重试保存，不重发检测；过期结果不能清除其他账号或新一轮的在途记录。

## 上游响应模型不一致

分组风控启用后，可单独选择“关闭此项检测”“立即停止账号调度并通知”或“立即通知，继续调度”。新增选项默认关闭，已有配置缺少 `model_mismatch_action` 时也按关闭处理。该选项独立于容量和定时测试通知开关：`stop` 和 `notify_only` 均创建企业微信通知，机器人仍复用对应分组的自动补号规则。

比较实际发送到上游的模型（经过渠道、账号和协议映射后的名称）与上游原始响应的模型声明，沿用使用日志的模型比较规则。流式请求在收到模型声明时处理，无需等待生成完成、账单入队或定时探针；覆盖 Responses、Chat Completions、Messages 转换、SmartWS/原生 WebSocket 及其 HTTP 回退。未声明模型、模型名大小写差异及既有比较规则认可的别名不触发；这不是比较回答正文，也不判断回答质量。

停调度模式只在当前账号身份、分组成员关系仍有效时操作，事务内同时保存停调度、处理记录与 scheduler outbox；更新调度快照后阻止后续调度，已接入的请求继续完成。通知失败不会恢复调度。仅通知模式不更改账号调度字段，其他容量和定时测试规则仍独立生效。

首次发现即生成待发送通知并唤醒通知工作器，不另等定时采样。发送仍遵守现有全站串行、至少间隔 3 秒的机器人限速；拥塞时可能排队。仅通知模式将同一账号一分钟内的重复异常合并并累计次数，第一条立即入队，持续异常在下一分钟可再次通知。关闭规则或本项检测会取消尚未开始发送的通知；已认领的消息可能完成。重启不重复发送结果不确定的消息。通知和最近处理记录明确区分“已停止调度”与“仅通知”。

## 上游 429 滚动窗口与手动测试

启用分组风控和“上游 429 过多时停止账号调度”后，默认最近 60 秒内超过 20 次，即第 21 次上游 429，直接关闭该账号调度。窗口可配置 1–3600 秒，阈值可配置 1–10000 次。按账号统计真实上游错误响应，重试请求若再次收到 429 也计一次；流式和 WebSocket 的等价限流终态同样计入。Redis 原子滚动窗口跨实例共享，过期自动删除，配置 revision、凭据身份或最近停调记录变化后重新计数。计数失败不伪造停调证据。旧配置缺少新开关时关闭该项，新规则默认参数为 60 秒 / 20 次。

次数达到条件后无需等待消息测试即可停调。通知沿用异常停调度通知开关，最近处理记录显示触发窗口和阈值。

“手动测试回复”选择此分组账号，点击“立即测试”，使用表单当前模型、思考强度、测试消息和期望内容，无需先保存。已停调账号也能测试；此操作不改变调度或保存配置。返回完整回复是否包含期望内容（区分大小写），只显示可见回复前 4096 字，匹配使用完整回复。上游错误、断流、繁忙和超时为检测未完成，不能视为不匹配。测试沿用手动/容量串行任务限制与账号并发槽；同一账号有其他检测时返回忙，不阻塞其他账号的全部模式定时检测，90 秒超时，消耗上游额度但不计入下游账单。回复正文只返回给本次管理员请求，不持久化。

`POST /api/v1/admin/accounts/risk-detection/test?group_id=ID`，请求为 `{ "account_id": ID, "revision": N, "config": { ... } }`。仅完整管理员允许；revision 冲突或有其他测试进行中返回 409。

## 停调度、状态与恢复

仅将异常账号的 `schedulable` 设为 false，现有请求继续完成。容量异常暂停的账号通过复测后自动恢复，其他停调原因仍需手动恢复。这个开关是账号级的，账号的其他关联组也受影响。

面板展示实际启用状态、容量、连续异常起点、下次测试、上次结果和最近 50 条风控处理记录。并发异常产生超过 50 条通知时，未发送和发送中的通知继续保留并逐条处理，不因界面的历史条数上限丢失提醒。全部模式额外展示每个账号的下次检测时间和上次结果。配置编辑不被后台刷新覆盖，保存使用 revision 防止覆盖其他管理员的修改。

状态与配置保存在现有 settings 的 `account_risk_detection_v1`；暂停队列独立保存在 `account_risk_capacity_pauses_v1`，避免蓝绿切换时旧实例覆盖新队列；每账号在途检测独立保存到 `account_risk_active_probes_v1`，并向旧版 `pending` 写入兼容占用标记，阻止排空中的旧实例重复检测。真实旧版检测先完成再接续，无新表/迁移。独立 PostgreSQL advisory transaction lock 协调实例；停号、事件、scheduler outbox 同事务提交并更新调度缓存。上游请求不持数据库锁。最多 32 个规则，异常数据库状态不执行停号。

管理接口：完整管理员访问 `GET /api/v1/admin/accounts/risk-detection?group_id=ID`；`PUT` 同地址，body 为 `{ "revision": 0, "config": { ... } }`。受限管理员密钥不允许访问。

该功能独立于 SmartWS、补号、吸能、旧探针和恢复逻辑，不修改它们的开关。发布使用本机受限构建的固定镜像，服务器只拉取和运行；回退旧应用不删除配置和已停调度状态。
