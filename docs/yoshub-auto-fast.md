# 自动Fast

账号管理顶部的“自动Fast”按 OpenAI 分组保存规则，默认关闭，仅完整管理员可读写。规则在服务器每 10 秒检查一次，关闭浏览器不影响运行。所有构建在本机完成。

## 时间与额度

- 使用现有 `Account.SourceExpiresAt()`：号商回收标记优先，其次导入回收时间，缺少标记才使用账号实际到期时间。保留宽限不计入回收时间。
- 7D 使用**已用比例**。只读取现有 `codex_7d_used_percent` 被动快照，不发探针或生成请求。
- 默认阶段为 45 分钟 / 50%、30 分钟 / 65%、15 分钟 / 80%，最终 5 分钟无条件开启；全部可编辑。时间必须递减，同一时刻只采用已进入的最靠后阶段。
- 普通阶段低于阈值开启，等于或高于阈值关闭。例如 45 分钟已开Fast，到30分钟且已用70%时关闭；到15分钟且已用75%时重新开启。
- 数据默认 300 秒有效，可设置30–86400秒。缺失、非法、过期或已过额度重置时间的数据不能当0%；普通阶段保持当前开关，最终阶段仍强制开启。
- 回收时间、实际到期时间任一已过，或账号停止启用、离开规则分组、续期后退出时间段，退出接管。

## 接管与退出

直接操作现有账号级 `extra.openai_force_fast`，沿用现有上游priority和下游计费策略。Fast对账号关联的所有分组生效；不改变调度开关、凭据、模型、思考强度或其他额外字段。

首次进入有效规则保存原状态。关闭功能或退出接管恢复原状态；发现最后一次自动设置后有手动改动，退出时保留手动值。启用期间规则持续生效，手动值可能被下一轮覆盖。

保存时拒绝同一账号参与两个启用分组。成员关系后来变化造成重叠时，该账号暂停接管并恢复原状态，显示冲突原因。解除冲突后可自动继续。

## 一致性与权限

`GET/PUT /api/v1/admin/accounts/auto-fast?group_id=<id>`；PUT包含 `{revision, config}`，revision冲突返回409。分组授权管理密钥不能访问此功能。

规则和接管记录保存在settings的 `account_auto_fast_v1`。PostgreSQL事务advisory锁及全局10秒门协调多个实例。写开关使用新鲜账号版本CAS；只合并Fast字段。账号写入、scheduler outbox、状态和事件同事务，失败整笔回滚。提交后刷新调度快照。旧版本忽略新增settings key，回退前应关闭已启用自动Fast规则以恢复其接管状态。

限制：32个规则分组、每组2000账号、总计5000账号、每组1–12阶段。界面展示前200个账号和最近50次实际开关变更。账号版本冲突在下一轮重试，不记录虚假成功。

## 验证

单元测试覆盖阶段边界、阈值相等、最终强制、期限优先、续期、数据缺失和重置、关闭恢复、人工修改、分组冲突、并发实例、CAS和事务失败及API权限。前端测试覆盖完整参数保存、增删规则、校验、状态刷新和revision冲突。

发布验收使用临时数据库/Redis与本机预编译镜像，验证真实后台定时检查、双实例、原账号开关、默认关闭与旧版本兼容。正式入口校验版本、静态资源、管理员API和原有配置指纹。
