# OVH IPv6 自动分配

IP 池顶部的「OVH IPv6 自动分配」默认关闭。开启后，自动补号和受限管理
API 的 `proxy_mode=random` 在账号写事务中领取一个新地址；关闭后恢复手工
代理池的随机空闲分配。开关不改变已有账号的代理。`least_used` 仍使用手工池。

只有成功绑定账号的地址才进入代理列表。每个地址只属于一个母账号；同一
凭据的 Spark 影子继承母账号出口。过期、额度耗尽、暂停和禁用不释放地址。
删除母账号或更换其代理，会永久退役旧地址；新连接停止，已有 CONNECT
连接自然结束后清除地址。后台每 5 秒同步退役，失败保留任务并重试。

地址按 OVH 路由前缀与十进制递增序号计算，不枚举候选地址。序号使用大整数，
支持 /56 的全部 72 位主机空间。零号保留给已有主地址；配置冲突、连通失败、
数据库回滚和测试消耗的编号均不再使用。数据库只保存当前绑定和未完成清理；
宿主机独立持久化递增高水位及当前租约，不保留逐 IP 的退役历史。

宿主机代理只连接公网 IPv6 的 80/443 端口，按租约固定源地址，通过 HTTP
CONNECT 保留端到端 TLS。没有 AAAA 记录、IPv6 出口故障或租约失效时请求失败，
不会自动改走 IPv4 或直连。托管代理不能编辑认证、放宽共享上限或用作备用代理。
备份导出不会携带托管出口凭据；导入此类账号需明确重新分配出口。

## 部署与回滚

见 [出口服务说明](../deploy/ovh-ipv6-egress/README.md)。`/app/ipv6-egress` 与主程序
由同一提交构建进入镜像；从不可变镜像提取到宿主机，不在生产现场构建。
应用通过 Docker 内网访问服务；控制密钥仅置于宿主机 0600 配置和应用环境。

迁移 251 为新增表和触发器，兼容应用旧槽位。发布时先验证独立出口服务，
再启新应用槽位、健康检查、切路由，等待旧槽位连接自然排空。数据库、Redis、
主机主 IPv6 和路由不需要重启或替换。应用回滚时保留新增表、出口服务及
高水位；旧版本不能管理新分配开关，回滚前应关闭自动分配。已有代理仍可工作，
退役清理需要支持本功能的应用恢复运行。

数据库恢复不能回退宿主机高水位。宿主机完整恢复必须保留最大的已发号值；
若最新计数副本全部丢失，停止分配并恢复可信高水位，不能根据现存账号猜测。
